# Pada for React — Blueprint

The library (`projects/pada-ds`, published as `pada-ds`) is the React twin of
[`pada-ds-angular`](https://github.com/supreeth-kashyap/pada-ds-angular). Same components, parts,
keyboard maps, tokens and motion. How to build a component, step by step:
[`docs/contributing.md`](docs/contributing.md).

## Repository layout

```
pada/
├── projects/pada-ds/   the library (npm workspace "pada-ds")
│   ├── src/headless/   pada-ds/headless: behaviour, keyboard, focus, ARIA, state attributes
│   ├── src/components/ pada-ds: the styled layer, one folder per component (tsx, css, stories, tests)
│   ├── src/styles/     tokens.generated.css (generated), base.css
│   ├── src/stories/    Storybook docs pages (MDX)
│   ├── tokens/         the token model (index.mjs, palette.mjs, legacy-names.json)
│   ├── scripts/        token build and checks, API manifest, 1.x token codemod
│   └── .storybook/
├── site/               the website: landing page and docs (npm workspace "pada-site")
├── content/            docs content (components/*.md → docs.json) shared by the site and both Storybooks
├── docs/               contributing guide, migration guide, roadmap
├── scripts/            repo tooling: Angular token sync, consumer smoke test, package docs copy
└── public/             brand assets served by Storybook and the site
```

The layout mirrors `pada-ds-angular` (`projects/pada-ds`, `docs/`, `scripts/`, `public/`).

## Two layers

1. **Headless** (`pada-ds/headless`, `src/headless`): behaviour, keyboard handling, focus, ARIA and
   state attributes. No styles. Parts accept `asChild` to merge onto the consumer's element.
2. **Styled** (`pada-ds`, `src/components`): the Pada look, built only from tokens, composing the
   headless parts. Components with parts are compound (`Dialog.Root`, `Dialog.Content`, …); simple
   ones are single components with props.

No component fetches data.

## Tokens

Every token is defined once in `tokens/index.mjs` and generated by `scripts/build-tokens.mjs`.

| Tier | Prefix | Example | Role |
|---|---|---|---|
| 0 Reference | `--pada-ref-*` | `--pada-ref-indigo-500` | Raw ramps and scales. Components never read these. |
| Palette | `--pada-palette-<intent>-*` | `--pada-palette-accent-600` | Ramps by intent (accent, neutral, success …). |
| 1 Semantic | `--pada-color-*`, `--pada-font-*` … | `--pada-color-fg-muted` | Meaning; light and dark in one `light-dark()` value. |
| 2 Derived | same | `--pada-color-accent-solid-hover` | `calc()` / `color-mix()` from tier 1 and the knobs. |
| 3 Component | `--pada-<component>-*` | `--pada-button-bg` | Declared at the top of each component's CSS; variants only reassign these. |

Knobs (`--pada-accent-hue`, `--pada-radius-base`, `--pada-density`, `--pada-type-base`,
`--pada-type-ratio`, `--pada-motion-scale`, `--pada-contrast`) drive the derived tier. Theme axes
are attributes that work on any element: `data-theme`, `data-accent`, `data-neutral`,
`data-density`, `data-radius`, `data-motion`, `data-contrast`.

## Rules

1. **State lives in attributes.** `aria-*` for interactive state, `disabled`, and `data-*` for
   variants (`data-size`, `data-variant`). Never modifier or state classes (`button--sm`,
   `is-active`), never `clsx`.
2. **Variants reassign component tokens** on the root (`.button[data-size="sm"] { --pada-button-height: … }`).
   No combinators for variants (`.parent--x .child`).
3. **Tokens only.** Component CSS reads tier 1–3 tokens. No raw colours, `--pada-ref-*` or
   `--pada-palette-*`. `tokens.generated.css` is never edited by hand. `npm run tokens:check`
   enforces this.
4. **One structural class per element** (`.tabs`, `.tab`, `.tab-panel`). JSX stays boring: no
   styling logic or conditional class names.
5. **Controlled and uncontrolled** through `useControllableState`.
6. **Focus management is scoped** to the component root (refs), never `document.querySelectorAll`.
7. **Parity with Angular.** Parts, attributes, keyboard behaviour and tokens match
   `pada-ds-angular`; differences are deliberate and documented in the component's doc comment.
8. **Every component ships with tests**: behaviour, keyboard, ARIA and an axe check, plus stories.

## Commands (repo root)

| Command | What it does |
|---|---|
| `npm run lint` | ESLint over the library and the site |
| `npm test` | Script tests (`node --test`) and component tests (Vitest, jsdom) |
| `npm run tokens:check` | Generated tokens are fresh; component CSS reads only defined tokens |
| `npm run build` | Library build: JS, types, tokens, manifest, llms files |
| `npm run check:manifest` | `llms.txt` / `llms-full.txt` are up to date |
| `npm run smoke:consumer` | Packs the library and installs it into a fresh Vite app |
| `npm run docs:data` | Rebuilds `content/docs.json` from `content/components/*.md` (`npm test` checks it) |
| `npm run storybook` | Storybook (composes the Angular Storybook) |
| `npm run dev` / `npm run build:site` | The website |
